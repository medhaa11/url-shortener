# URL Shortener with Analytics

A production-resembling URL shortener built from scratch in Python and FastAPI, featuring click analytics, a visual dashboard, Redis caching, and rate limiting.

---

## Features

- **URL Shortening** — Paste any long URL and get a short, shareable link instantly
- **Click Tracking** — Every redirect logs the visitor's device type, referrer, and IP
- **Analytics Dashboard** — Per-link dashboard with charts for clicks over time, device breakdown, and top referrer sources
- **Redis Caching** — Short code lookups are cached in Redis using the cache-aside pattern, eliminating repeated DB reads
- **Rate Limiting** — Sliding window rate limiter (5 requests/min per IP) built on Redis sorted sets
- **Base62 Encoding** — Short codes are generated by encoding the auto-incremented row ID into Base62

## How It Works

### URL Shortening
1. User submits a long URL via `POST /shorten`
2. URL is inserted into SQLite, returning an auto-incremented integer ID
3. The ID is encoded into a Base62 string (e.g. `14` → `"e"`) to create the short code
4. Short code is written back to the DB row and cached in Redis
5. User is redirected to the homepage with their new link

### Redirecting
1. `GET /{short_code}` checks Redis first
2. On cache hit → serves the URL directly, skipping the DB lookup
3. On cache miss → queries SQLite, writes result to Redis for next time
4. Click is logged to the DB on every request (device, referrer, IP)

### Analytics Dashboard
- `GET /dashboard/{short_code}` runs four SQL aggregation queries
- Returns total/today/weekly click counts, a 30-day time series, device breakdown, and top 5 referrers
- Chart data is serialized via `json.dumps()` and embedded into the HTML for Chart.js to render client-side

### Rate Limiting
- Each IP gets a Redis sorted set keyed as `rate:{ip}`
- Every request adds the current Unix timestamp as a member
- Timestamps older than 60 seconds are pruned on each request
- If the remaining count exceeds 5, the request is rejected with a 429
- All four Redis operations are batched in a single pipeline call

## Getting Started

### Prerequisites
- Python 3.12+
- Redis running locally (`brew install redis && brew services start redis` on Mac)

### Installation

```bash
# Clone the repo
git clone https://github.com/medhaa11/url-shortener.git
cd url-shortener

# Create and activate virtual environment
python -m venv url-shortener-env
source url-shortener-env/bin/activate

# Install dependencies
pip install -r requirements.txt

# Start the server
uvicorn main:app --reload
```

Visit `http://127.0.0.1:8000`

## Database Schema

```sql
CREATE TABLE urls (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    short_code   TEXT UNIQUE,
    original_url TEXT NOT NULL,
    created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    expires_at   DATETIME
);

CREATE TABLE clicks (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    url_id       INTEGER REFERENCES urls(id) ON DELETE CASCADE,
    clicked_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    ip_address   TEXT,
    device       TEXT,
    referrer     TEXT
);
```

## Key Concepts Demonstrated

- **Base62 encoding** — integer-to-string encoding for short, URL-safe codes
- **Cache-aside pattern** — Redis as a read-through cache with TTL-based expiry
- **Sliding window rate limiting** — Redis sorted sets for true per-IP rate limiting
- **SQL aggregation** — `GROUP BY`, `COUNT`, `DATE()` modifiers for analytics queries
- **HTTP redirect semantics** — 302 vs 301 and why 302 is required for click tracking
- **Separation of concerns** — analytics, caching, encoding, and DB logic in separate modules
